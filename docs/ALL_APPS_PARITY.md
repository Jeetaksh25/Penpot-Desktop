## 1. Executive summary & cross-cutting themes

Ovion Desktop is a Tauri v2 shell around Penpot's ClojureScript frontend with the full
local JVM/Postgres/Redis backend in-process. On top of Penpot it adds a two-layer AI
pipeline (CLJS → Tauri → `llm.rs`), client-side code export to 7 UI frameworks, a Google
Fonts proxy, region-select, URL-clone, the `.ovion` format, and a smart Auto/Max model
router (DeepSeek V4 Flash). The research surfaced **96 deduplicated gaps**
(**19 P0**, **36 P1**, **41 P2**) across the 10 tools: 63 missing, 30 half-done, 3 not-working.

The eight cross-cutting themes:

1. AI is single-shot, not iterative: Ovion uses a preview-then-Apply flow with one preview per fire and an 8-step agent loop; it cannot stream generation to canvas mid-build, produce N variants side-by-side, create non-destructive alternatives preserving the original, or run parallel idea branches — capabilities Figma Stitch, Uizard, and UXPin all treat as core exploration loops.

2. No external-agent surface (MCP): Ovion's AI is a closed internal two-layer pipeline (CLJS -> Tauri -> llm.rs) with a curated ai_tools.cljs registry; it exposes no MCP server for Cursor/Claude Code/Codex/Windsurf to read or drive the design surface, and the existing MCP client namespace is dead code on desktop. Five of ten tools (Sketch, Pixso, Lunacy, Webflow, Google Stitch) ship or plan local MCP servers.

3. AI generation is unconstrained by the design system: generate-design applies a free-form DesignSpec emitting absolute-positioned frames; no logic pulls hex from global variables, reuses library components, snaps to spacing grids, obeys an authorable brand-guidelines document, or accounts for classes/tokens created vs reused (Pixso, UXPin Forge, Webflow AI Assistant all enforce this).

4. Prototype logic is schema-only and not runtime-evaluated: conditionals, set-variable, and expressions are DECLARED in interactions.cljc but the viewer dispatch in viewer/shapes.cljs has no :conditional/:set-variable branch and there is no Condition Builder UI or fx expression editor — Axure's signature if/else-if + variable-driven logic and UXPin's Variable Change trigger have no runtime.

5. Web-builder category is entirely absent: Ovion is a fixed-canvas vector design tool, not a responsive web builder — no CMS/collections, no managed hosting/CDN/staging, no responsive breakpoint cascade, no scroll-driven animations, no real HTML/CSS DOM-editor authoring, no forms/SEO/e-commerce. Framer and Webflow define this category and Ovion has none of it.

6. Vector craftsmanship tools are stubbed or runtime-no-op under the no-build/render-wasm-off constraint: Shape Builder and paint-bucket are registered text-badge stubs, outline-stroke is gated on render-wasm/v1 (OFF), offset-vector is polyline-only, and the Pathfinder panel (Divide/Trim/Merge/Crop/Outline/Minus-Back) does not exist — the geometry engine (bool.cljc) is present but the interactive region layer and production ops are missing.

7. AI image models are entirely missing: no text-to-image, background-removal/segmentation, upscaling, or people-photo generation model is wired in llm.rs; Figma_Parity #41 is scope-deferred because it needs a Rust ML module blocked by the no-.rs constraint, so every competitor's one-click image asset/edit workflow is absent.

8. Accessibility is contrast-only: ui/inspect/a11y.cljs runs a single-shape WCAG contrast check with no styling; there is no color-blindness/vision-deficiency simulator, no ARIA label/role authoring, and because prototypes render as SVG (not real DOM/React) screen readers cannot meaningfully interact with them — UXPin's code-level accessibility and Framer's site audit have no analogue.

## 2. Shape Builder deep-dive — the #1 priority

*Adobe Illustrator's Shape Builder (Shift+M) is the canonical interactive boolean-
composition tool and the user's explicitly highest-priority parity target. The full
research writeup follows, lightly reformatted from the synthesis agent's output.*

### WHAT AI SHAPE BUILDER DOES
Adobe Illustrator's Shape Builder (Shift+M) is the canonical interactive, modal, direct-on-canvas boolean-composition tool. Its defining UX is hover-region highlighting: given a set of selected overlapping paths, Illustrator computes a planar arrangement of "faces" (closed, non-overlapping regions bounded by path segments) and "edges" (path segments that do not cross another path), then dynamically highlights the exact face or edge under the cursor in real time before any click. In default merge mode (cursor shows +): click-dragging across multiple highlighted faces unites them into one shape (a red outline follows the drag); a single click on one face isolates it as its own independent path (equivalent to Pathfinder > Divide); clicking an edge deletes that segment. Holding Alt/Option switches to erase mode (cursor shows -) where click/drag removes faces or edges. It works on both closed and open paths (with a "consider open filled paths as closed" option), performs Gap Detection to bridge small openings so imperfect pen-tool line art still closes regions, and can apply fill color during the merge (Pick Color From: Artwork inherits the first-touched face's color; Color Swatches uses the active swatch with a live Cursor Swatch Preview). It targets illustrators/icon designers/logo artists who compose by feeling rather than by naming set operations. The sibling Pathfinder panel (Window > Pathfinder) exposes the same boolean math as one-shot buttons: Shape Modes (Unite/Minus Front/Intersect/Exclude — Alt-click for non-destructive Compound Shapes) and Pathfinders (Divide/Trim/Merge/Crop/Outline/Minus-Back), plus Effect-menu-only Hard Mix/Soft Mix/Trap. Compound Shapes are the live, non-destructive counterpart: a container that keeps every original sub-path independently editable and re-evaluates the combination on every edit, with each child carrying its own shape-mode (add/subtract/intersect/exclude).

### WHAT OVION/PENPOT CURRENTLY HAS
Ovion inherits Penpot's solid boolean engine. app/common/types/path/bool.cljc implements the four Shape Modes — create-union, create-difference, create-intersection, create-exclusion — as both destructive and non-destructive operations. The non-destructive :bool shape keeps its :shapes children and recomputes :content via ui/shapes/bool.cljs when content is nil; change-bool-type re-runs the combination without destroying children (functionally equivalent to an Illustrator Compound Shape at the whole-group level). The sidebar options menu (sidebar/options/menus/bool.cljs) exposes these four ops plus Flatten as radio buttons, and the context menu wires flatten/convert-to-path. The underlying geometry helpers (line-line, line-curve, curve-curve intersection, split-ts) exist in bool.cljc and could be reused. Related vector ops are present but runtime-inactive: outline-stroke (shapes_to_path.cljs L235-252) delegates to wasm.api/stroke-to-path GATED on the render-wasm/v1 flag which is OFF in the desktop build (safe no-op); offset-vector (L297-323) is a basic vertex-normal miter offset that flattens curves to a polyline. The :shape-builder and :paint-bucket edit-modes are REGISTERED in ui/workspace/shapes/path/editor.cljs (L513-535) — toolbar/shortcut selectable — but their interactive geometry is explicitly DEFERRED: only a guarded text badge renders. Comments at L517-520 confirm "#28 — drag merge/extract/subtract via the boolean engine is not yet wired" and "#29 — enclosed-region (graph-cycle on path nodes/segments) detection and filled sub-path creation is not yet wired." Figma_Parity.md L221-222 states "No shape-builder anywhere." translations/en.po has zero labels for Unite/Minus Front/Intersect/Exclude/Divide/Trim/Merge/Crop/Outline/Minus-Back/Hard Mix/Soft Mix.

### THE PRECISE GAP
1. No interactive hover-region highlight — the entire point of Shape Builder versus Ovion's named-op radio buttons. Ovion requires the user to pick union/difference/intersection/exclude and apply it to whole shapes; Illustrator lets the user see and grab a single sub-region of the combined arrangement without thinking in set-theoretic terms. The :shape-builder mode renders only a text badge.
2. No face-arrangement computation — the geometric prerequisite. bool.cljc has the 4 Shape Modes but no Divide/face-splitting routine that returns the full set of non-overlapping faces with their owning sub-paths. Shape Builder's hover model requires: compute all intersection points, split every crossing path into edges, form the planar face graph, then identify the face under the cursor.
3. No click-drag-to-merge gesture across arbitrary sub-regions; no Alt/Option erase gesture on any face/edge of an N-path arrangement (Ovion's :difference is a whole-shape top-minus-bottom op requiring selection ordering); no edge-deletion primitive.
4. No Pathfinder panel — only 4 Shape Modes exist; Divide/Trim/Merge/Crop/Outline/Minus-Back and Hard/Soft Mix/Trap are entirely absent (no i18n surface, no UI).
5. No Compound-Shape per-child shape-mode overrides — Ovion's bool-type is a single radio applied to the WHOLE group; Illustrator lets each child carry its own add/subtract/intersect/exclude mode in a hierarchy. No Expand-to-finalize button (Flatten is destructive-only).
6. No paint-bucket flood fill (enclosed-region graph-cycle detection) — the Figma-equivalent region-click-to-fill, registered as a stub.
7. No Gap Detection / open-path-as-closed tolerance — bool.cljc requires genuine geometric intersection, so an open path or sub-pixel gap yields no region; a Shape Builder built on the existing engine would fail on imperfect pen-tool output.
8. Outline-stroke runtime-inactive (gated on render-wasm/v1 OFF) and offset-vector polyline-only — the surrounding vector-production toolkit is half-broken.

### RECOMMENDED BUILD PLAN
Phase 1 — Face-graph engine (pure CLJC, no renderer dependency, unblocked by the no-build constraint since it is Clojure data logic): Implement a planar arrangement routine in a new common/types/path/arrangement.cljc that reuses bool.cljc's intersection helpers. Algorithm: (a) collect all path segments from selected shapes; (b) compute all pairwise segment intersections (line-line/line-curve/curve-curve already exist); (c) split every segment at its intersection points into edges; (d) build the planar subdivision via a half-edge/doubly-connected-edge-list (DCEL) — each face records its bounding edges and the owning sub-paths; (e) add a point-in-face test (winding/odd-even) for cursor hit-testing. Add a Divide op on top that returns all faces as independent paths. Add a gap-tolerance parameter that snaps near-coincident endpoints (configurable px threshold, default small) and an open-path-as-closed toggle so pen-tool output works.
Phase 2 — Interactive Shape Builder mode (frontend overlay, no WASM): In ui/workspace/shapes/path/editor.cljs replace the :shape-builder stub badge with a real edit-mode. On mode enter, run the face-graph engine on the current selection and cache the arrangement. Add a cursor-tracking overlay (reuse the pixel_overlay.cljs machinery used by the loupe) that highlights the face/edge under the cursor using the point-in-face test. Implement three gestures: (1) click face -> isolate as its own path (Divide-equivalent); (2) press-drag across faces -> unite touched faces into one shape (red outline follows drag, reuse create-union on the face sub-paths); (3) Alt/Option held -> erase mode, click/drag deletes faces/edges (remove the face's sub-path contribution). On commit, write the result via the existing shape mutation path (dmstr-style) and invalidate the cached arrangement.
Phase 3 — Pathfinder panel: Add sidebar/options/menus/pathfinder.cljs exposing two rows: Shape Modes (Unite/Minus Front/Intersect/Exclude — already backed by bool.cljc) and Pathfinders (Divide = Phase-1 face-split; Trim = remove hidden parts + strokes; Merge = unite same-fill faces; Crop = top-object clip mask; Outline = edges-as-unfilled-segments; Minus-Back = reverse difference). Wire each to a bool.cljc routine; add i18n labels to en.po. Alt-click on Shape Modes creates a non-destructive :bool (already supported) — extend the bool schema so each :shapes child can carry its own :shape-mode override (add/subtract/intersect/exclude) instead of one radio for the group, and update bool.cljs content recompute to honor per-child modes. Add an Expand button that finalizes a live :bool into a static :path (distinct from Flatten in that it preserves a copy of the live original for undo).
Phase 4 — Paint-bucket flood fill: Implement enclosed-region detection as graph-cycle detection on the path node/segment topology (a bounded region is a cycle of segments enclosing no other un-split region); on click, create a filled sub-path for the bounded region. Reuses the Phase-1 face graph.
Phase 5 — Surrounding ops: Un-gate outline-stroke by implementing a frontend stroke-to-path (offset each side of the stroke outline by half-width and close) so it works on the SVG renderer without render-wasm/v1; upgrade offset-vector to a true curve offset (offset the Bezier control polygon + re-derive handles, with miter/round/bevel join selection and self-intersection cleanup via the Phase-1 arrangement). Add live Offset Path as an effect-style entry alongside the destructive Object command.
Priority note: Phase 1 is pure data logic and can land immediately under the no-build constraint; Phases 2-4 are frontend overlay/UI work (ClojureScript + en.po), also unblocked; Phase 5's outline-stroke is the one piece that needs a non-WASM stroke-outline routine. This is the highest-ROI vector-craftsmanship investment because the geometry engine already exists — the missing piece is the face-graph layer and the interactive gesture/overlay, not new boolean math.

## 4. Per-tool findings

### Sketch

**Overview:** Sketch is the macOS-native vector design tool (Sketch B.V.), sold as a Mac app plus a free web workspace for developer handoff. Its 2025-2026 arc shipped three major releases (Athens/Barcelona/Copenhagen in 2025, Dublin/Edinburgh in 2026): a new Stacks auto-layout system replacing Smart Layout, Frames/Graphics containers, a from-scratch Glass effect for iOS 26/macOS 26 Liquid Glass, progressive blurs, on-device background removal via Apple Vision, and a complete macOS Tahoe UI redesign. Its headline AI play is a local-only MCP server that lets external AI clients (Claude Code, Cursor, Codex) drive Sketch via a run_code SketchAPI tool. It targets product/UI designers on macOS who want native performance, deep component/library/override semantics, and privacy-first AI via an open agent protocol.

**Standout features:**

- **Local MCP Server for AI agents** — A local-only Model Context Protocol server (off by default, started via Cmd+K > 'MCP', served at localhost:31126/mcp) that lets any MCP-compatible AI client (Claude Code, Cursor, Codex, Antigravity) connect to Sketch. Exposes tools: run_code (execute arbitrary SketchAPI JavaScript), get_document_info, get_layer_tree_summary, get_design_assets, get_screenshot, get_libraries, get_symbol_overrides, get_guide. No tokens, no add-ons, runs on the user's Mac, supports local models for fully on-device workflows. *Why it matters:* It is Sketch's entire AI strategy: instead of baking one fixed model in, it exposes the document to ANY external AI agent that can write/debug SketchAPI JS, check its own work via screenshots, and iterate. A Penpot/Ovion user currently only has Ovion's closed GLM/Kimi agent loop; they cannot point Claude Code or Cursor at their file and ask it to swap themes, build a palette, or generate code with 1:1 fidelity.
- **On-device one-click background removal** — Copenhagen (2025.3) added one-click background removal for people/objects using Apple's on-device Vision ML framework. Images never leave the Mac. No third-party calls. *Why it matters:* A daily asset-prep task done in-place with a click. Ovion's AI image editing (remove-bg/erase/isolate/expand) is explicitly SCOPE-DEFERRED-v1 (Figma_Parity #41) because it needs a segmentation/inpainting Rust module; Ovion users must leave the app to cut out a subject.
- **Stacks (auto-layout) with wrapping** — Athens (2025.1) replaced Smart Layout with Stacks: padding, alignment, distribution, per-item fill/align/ignore options, and (Copenhagen) horizontal + vertical wrapping. More predictable than Smart Layout, which is still supported on legacy Symbols. *Why it matters:* Wrapping stacks (column-wrap) are a top-requested responsive-layout primitive. Ovion has Penpot auto-layout (flex + CSS grid, layout_container.cljs/frame_grid.cljs) which is arguably broader (grid), but Sketch's wrap behavior and per-item layout opt-out are a benchmark for responsive component design.
- **Glass, Progressive Blur, and Fade effects** — Barcelona (2025.2): Glass effect built from scratch for iOS 26/macOS 26 Liquid Glass; Progressive blurs in linear and radial forms with on-canvas adjustable stops (like gradient stops); Fade = gradient-based transparency without alpha masks, stops draggable on canvas. *Why it matters:* These are the effects designers need for current Apple platform work. Ovion has glass (#61) and progressive blur (#60) wired as schema+UI only with the renderer DEFERRED under the no-build constraint, and no Fade tool at all, so it cannot visually produce Liquid Glass or gradient-fade output today.
- **Concentric (Auto) Corners** — Athens (2025.1): a corner mode that automatically calculates a layer's corner radius based on proximity to its nearest container, producing visually harmonious nested corners without manual math. *Why it matters:* Removes the manual fiddling of nested corner radii. Ovion has corner smoothing/squircle (#2) and per-corner radii but no proximity-based auto-concentric calculation.
- **Vector toolset: 4 point types, Scissors, Rotate Copies, Offset Path, Convert to Outlines** — Vector mode (V/Return) with four point types switchable via Inspector or number keys 1-4 (Straight, Mirror angle+length, Independent, Mirror angle); Layer > Path > Scissors (cut lines/borders); Layer > Path > Rotate Copies (radial duplicates around a point); Layer > Path > Offset (robust expand/contract); Cmd+Opt+O Convert to Outlines (borders -> filled shapes); pixel snap to full/half/quarter. *Why it matters:* These are Sketch's signature vector craftsmanship tools. Ovion's offset-vector is polyline-only (curves flatten), outline-stroke is a no-op gated on the render-wasm/v1 flag, and Scissors/Rotate-Copies have no equivalent in the toolbar or path editor at all.
- **Non-destructive booleans incl. Add (open-path merge)** — Five boolean ops: Union, Subtract, Intersect, Difference (= exclude), and Add (Cmd+Opt+A) which combines open paths without a boolean operation. Non-destructive, re-typable per sub-layer from the Layer List. *Why it matters:* Add is the one that handles open-path compositing (e.g. merging stroke outlines) that pure boolean union can't. Ovion has union/difference/intersection/exclusion (4 ops) but no open-path Add merge.
- **Symbols, Overrides, and Libraries** — Symbols (Source + Instance) with nested Symbols; Overrides for text, colors, images, nested Symbols, Layer/Text Styles, hide-layers-in-instance, reset overrides; markdown-like text-override styling (**bold**, __italic__, [underline]); Libraries = shared documents of Symbols/Text Styles/Color Variables/Layer Styles/frame templates with update notifications and starred versions; Replace Library ~15x faster (Edinburgh). *Why it matters:* The mature component/override/library model is Sketch's core repeatable-design engine. Ovion has Penpot components+variants+typed properties (component.cljs) and shared libraries (libraries.cljs) which cover this, but the markdown text-override styling and starred library versions are Sketch-specific niceties.
- **Prototyping: Overlays, Hotspots, scroll groups, sticky/fixed, multiple start points** — Overlays (modals/menus) with position, backdrop, and Hover/Press/Toggle/Click triggers; Hotspots (clickable areas larger than one layer); scroll areas (vertical/horizontal/multi) inside frames; pinned/fixed elements (sticky headers); maintain-scroll-position after click; multiple Start Points; prototype panel docked separately from the Inspector (Copenhagen). *Why it matters:* Reassures that Ovion is largely at parity here: Ovion's interactions.cljs already exposes mouse-over/press/enter/leave/key-down/on-change/after-delay triggers plus toggle-overlay and scroll-to actions, so this is NOT a gap - listed for completeness.
- **2026 power features: Selection Colors, Independent Borders, Oklab/Oklch gradients, Multi-Paste** — Dublin (2026.1): Selection Colors (adjust colors across multiple selected layers, sort by frequency/color), Independent Borders (per-side, center dashed borders on corners), corner-smoothing 'Max' option, eyedropper picks Color Variables (hold Shift). Edinburgh (2026.2): Perceptual (Oklab) and Vibrant (Oklch) gradient interpolation, Multi-Paste (Paste/Paste Over/Paste & Replace across multiple layers), Copy Properties (fills/borders/shadows/effects/size/position/interactions), Design Tokens export (DTCG v2025.10). *Why it matters:* These are the latest workflow accelerants. Ovion has per-side stroke widths (#4) and DTCG import/export, but lacks multi-layer selection-color editing, Oklab/Oklch gradient interpolation, and multi-paste - small but real productivity gaps.

### Adobe Illustrator Shape Builder

**Overview:** Adobe Illustrator's Shape Builder (Shift+M) is the canonical interactive, modal, direct-on-canvas shape-composition tool, sitting atop the broader Pathfinder / compound-shape feature family. Its defining UX is hover-region highlighting: when overlapping selected paths are present, Illustrator computes an arrangement of non-overlapping "faces" (closed regions) bounded by "edges" (path segments that don't cross another path) and dynamically highlights the face/edge under the cursor in real time. In default merge mode (cursor shows +), click-dragging across faces unites them into one shape, clicking a single face isolates it as its own path (equivalent to Pathfinder > Divide), and clicking an edge deletes it. Holding Alt/Option switches to erase mode (cursor shows -) where click or drag removes faces/edges. It works on both closed and open paths (with a "consider open filled paths as closed" option), performs Gap Detection to bridge small openings, and can even apply fill color during the merge ("Pick Color From: Artwork" inherits the first-touched face's color, or "Color Swatches" uses the active swatch with a live Cursor Swatch Preview). It targets illustrators/icon designers/logo artists who compose by feeling rather than by naming operations. The sibling Pathfinder panel (Window > Pathfinder) exposes the same boolean math as named one-shot buttons in two rows: Shape Modes (Unite, Minus Front, Intersect, Exclude — Alt-click for non-destructive Compound Shapes) and Pathfinders (Divide, Trim, Merge, Crop, Outline, Minus Back), plus Effect-menu-only Hard Mix / Soft Mix / Trap. Compound Shapes are the key non-destructive counterpart to Ovion's :bool — a live container that keeps original sub-paths editable and re-evaluates the combination on every edit; Compound Paths are a flatter hole/transparency construct using even-odd/non-zero winding. Surrounding the family are Offset Path (Effect = live, Object = destructive; miter/round/bevel joins + miter limit), Outline Stroke (stroke -> filled path), Expand / Expand Appearance (finalize live effects/strokes into anchor-point paths), and Divide (face-splitting). Ovion inherits Penpot's solid destructive+live boolean engine (union/difference/intersection/exclude with a non-destructive :bool that recomputes content from children, plus Flatten/convert-to-path) but has NONE of the interactive region-based UX: the :shape-builder edit-mode is registered as a stub text-badge only (editor.cljs lines 524-535), with no hover-region detection, no drag-to-merge/erase overlay, no edge deletion, no gap detection, and no Pathfinder panel (no Divide/Trim/Merge/Crop/Outline/Minus-Back/Hard/Soft-Mix). Outline-stroke and robust offset are present in menus but runtime-no-op or polyline-only.

**Standout features:**

- **Hover-region / hover-edge live highlight** — On hovering over selected overlapping artwork, Illustrator pre-computes the arrangement of faces (closed non-overlapping regions) and edges (uncrossed path segments) and renders a colored highlight over exactly the face/edge under the cursor before any click, so the user sees precisely what will be merged or erased. *Why it matters:* This is the entire point of Shape Builder versus Ovion's boolean radio buttons. Ovion's :bool requires the user to name an operation (union/difference/intersection/exclude) and apply it to whole shapes; Illustrator lets the user see and grab a single region of the combined arrangement without thinking in set-theoretic terms. Without hover-region highlight there is no Shape Builder — Ovion's current stub only renders a 'shape-builder' text badge.
- **Click-drag to merge faces across regions** — Default merge mode: press-drag across multiple highlighted faces and they unite into a single shape; a red outline follows the drag. A single click isolates one face as its own independent path (Divide-equivalent). *Why it matters:* Ovion can only union entire selected shapes via the bool menu. Dragging across arbitrary sub-regions of an arrangement is a fundamentally more expressive interaction — one gesture composes a logo/icon face that would otherwise need several boolean ops plus manual Divide + delete. Ovion's bool engine already contains the geometry (create-union in bool.cljc) but exposes no per-region gesture.
- **Alt/Option erase mode (click/drag to delete faces + edges)** — Holding Alt/Option flips the cursor to erase; click a face to delete it, drag to remove several, or click an edge to remove that segment. This is the interactive analog of Minus Front/Crop without needing a top object. *Why it matters:* Ovion's difference operation requires a clearly ordered 'top minus bottom' pair. Shape Builder erase works on any face of an N-path arrangement regardless of stacking, which is how illustrators actually carve negative space. Ovion has no erase gesture at all.
- **Non-destructive Compound Shapes (Alt-click Shape Modes)** — Alt/Option-clicking Unite/Minus Front/Intersect/Exclude in the Pathfinder panel creates a Compound Shape: a live container in the Layers panel that keeps every original sub-path independently selectable, movable, recolorable, and editable, with the combination re-evaluated live; Release fully recovers originals. *Why it matters:* Ovion's :bool is already non-destructive in this spirit (keeps :shapes children, recomputes content via ui/shapes/bool.cljs when :content is nil, change-bool-type re-runs). So Ovion is actually close here — the gap is that there is no Pathfinder panel UI exposing per-child shape-mode overrides and no Expand-button to finalize, only the single bool-type radio on the whole group.
- **Pathfinder panel: 6 Pathfinders (Divide/Trim/Merge/Crop/Outline/Minus-Back)** — One-click destructive operations: Divide splits all overlaps into independent colored faces; Trim removes hidden parts and strokes; Merge unites same-colored faces; Crop uses top object as a clip mask; Outline turns all edges into unfilled line segments; Minus Back subtracts back-from-front. Plus Effect-menu-only Hard Mix/Soft Mix (CMYK primary mixing per face) and Trap (print registration). *Why it matters:* Ovion's bool engine only implements the 4 Shape Modes (union/difference/intersection/exclude). Divide (face-splitting) is the geometric prerequisite for Shape Builder itself, and Trim/Merge/Crop/Outline are standard production ops. None exist in Ovion — en.po has zero of these labels and there is no pathfinder panel.
- **Gap Detection + 'Consider open filled paths as closed'** — Shape Builder Options let the user set a gap size (presets or custom) so near-touching paths are treated as closing a region, and open filled paths can be treated as closed for merging — making the tool forgiving of imperfect line art. *Why it matters:* Real hand-drawn vector art (e.g. from a pen tool) rarely closes perfectly. Ovion's bool engine requires genuine geometric intersection; an open path or a hairline gap yields no region at all. Gap tolerance is essential for an interactive region tool to feel usable on Ovion's own pen-tool output.
- **Color application during merge (Pick Color From Artwork / Swatches + Cursor Swatch Preview)** — While dragging to merge, the result inherits fill from the first-touched face (Artwork mode) or from the active swatch (Swatches mode) with a live swatch cursor and arrow-key paging. *Why it matters:* Ovion's boolean result inherits fill by an internal rule and there is no in-gesture color choice. For icon/logo work where coloring and composing happen simultaneously, this is a meaningful workflow-speed gap.
- **Offset Path (live Effect + destructive Object), Outline Stroke, Expand/Expand Appearance** — Offset Path duplicates a path inward/outward by a distance with miter/round/bevel joins + miter limit, available as a live Appearance-panel effect OR a destructive Object command. Outline Stroke converts a stroke to a filled closed path. Expand/Expand Appearance finalize live effects and strokes into editable anchor paths. *Why it matters:* Ovion has outline-stroke wired (context menu do-outline-stroke) but it delegates to wasm.api/stroke-to-path gated on the render-wasm/v1 flag which is OFF in this desktop build, so it no-ops at runtime. offset-vector exists but is polyline-only (curves flatten). There is no live Offset Path effect and no Expand/Expand Appearance workflow.
